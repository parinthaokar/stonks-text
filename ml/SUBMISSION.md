## 3–5 sentences

> I chose **logistic regression** because the task is multiclass classification — the output
> is one of three discrete actions (sell / hold / buy), not a number — and logistic regression
> handles three classes natively via softmax, returning a probability for each; I also tested a
> random forest and gradient boosting, and since all three scored within noise of one another
> on held-out data, the added complexity bought nothing while logistic regression is the only
> one whose coefficients can be read directly to explain a prediction. The service takes ten
> strictly backward-looking numbers describing a single trading day — the day's move, volume
> against its 20-session average, realised volatility, distance from the 50-day average,
> drawdown from the 52-week high, two 52-week-extreme flags, up and down streak lengths, and a
> crypto flag — and returns a suggested action with a probability for each option. My custom
> transformer is **`MarketContextFeatures`**, which expands those ten raw inputs into
> twenty-one engineered features (magnitude and direction separated, log-scaled volume, capped
> streaks, and three interaction terms) with no hand-coded thresholds, so any decision boundary
> had to be learned rather than supplied. It is built and served on **scikit-learn 1.9.1**,
> pinned into `requirements.txt` from the interpreter that fitted the artifact. Evaluated on a
> temporal split with a 10-day embargo it scores 34.5% against a 36.9% majority baseline — it
> does **not** beat the baseline, which is the expected result for daily direction prediction,
> and the API returns that fact with every response so the interface reports it rather than
> implying confidence the model has not earned.

**Custom transformer:** `MarketContextFeatures` (in `ml/pipeline_def.py`)

## Checklist against the brief's "don't miss" list

| Failure mode | How it's avoided | Evidence |
|---|---|---|
| Custom class not in the Modal image | `modal_serve.py` ships `serve.py`, `pipeline_def.py` and `pipeline.joblib` with `copy=True`, and refuses to deploy if any is missing | `POST /recommend` returns 200 on the deployed URL — impossible to unpickle without the class |
| sklearn version mismatch | `requirements.txt` generated by `build_pipeline.py` from the interpreter that fitted the artifact | `GET /pipeline` reports `1.9.1`, matching the build |
| Load-per-request | Module-level load at import; a failed load is captured, never raised | 607 ms average across the Postman run; 503 on all routes when the artifact is removed, with the process still alive |
| Frontend still on localhost | `NEXT_PUBLIC_MODAL_API_URL` with **no localhost fallback** in `src/lib/recommendation.ts` | the deployed URL appears in the client bundle; `localhost:8000` appears in zero chunks |
| Postman hitting localhost | `base_url` collection variable = Modal URL, plus an assertion that fails if the host contains `localhost` | assertion "NOT hitting localhost" passes |

CORS is enabled and verified by preflight, because the browser calls this service directly —
without it every request fails in the browser while working perfectly from curl.

## On the accuracy

The model does not beat a majority-class baseline, and this is not hidden. Three framings
were tested before settling here — direction, volatility magnitude, and nearest-neighbour
historical analogy — and none beat their baselines on a temporal split with an embargo. That
is the expected result: predicting daily direction for twelve of the most heavily traded
assets in the world from public price history is the most-attempted problem in quantitative
finance, and it does not work.

It is reported as a finding rather than a flaw. The project's existing backtest already
reached the same conclusion from a different direction, when a coin-flip control that traded
on the same days returned +1.9%. Arriving at it twice, by different routes, makes it stronger.
